# リポジトリ構造定義書

## 概要
本書は、本リポジトリのフォルダ構成と、各フォルダ・ファイルの役割を定義する。ファイル名の具体的な命名規則（例：dbtモデルの命名パターン）は本書の対象外とし、開発標準（`docs/backlog.md` 014番）に委譲する。本書は「何がどこに置かれるか」という粒度に留める。

## ディレクトリ構成

```
practice_data_platform/
├── CLAUDE.md
├── docs/                      # 永続ドキュメント
├── .steering/                 # 作業単位のドキュメント
├── dbt/                       # dbtプロジェクト本体（コード）
│   ├── dbt_project.yml
│   ├── models/
│   │   ├── staging/
│   │   │   └── moneyforward/  # ソースシステム（取得元）ごとにフォルダを分ける
│   │   ├── intermediate/
│   │   └── marts/
│   ├── seeds/
│   ├── macros/
│   └── tests/
├── ingestion/                  # データ取り込み用スクリプト（コード）
└── sample_data/                 # 開発・テスト用のダミーデータ
```

## 各ディレクトリの役割

### `docs/`
データ基盤全体の「北極星」となる永続ドキュメントを格納する。基盤全体の設計・方針が変わらない限り更新されない。詳細は`CLAUDE.md`の「永続ドキュメントとその役割」を参照。

### `.steering/`
特定の開発作業単位のドキュメント（要件定義書・基本設計書・実装タスク一覧）を格納する。ディレクトリ命名規則（`.steering/[YYYYMMDD]-[開発タイトル]/`）は`CLAUDE.md`で定義済み。

各フォルダ内のファイル名は以下の固定名とする（日付はフォルダ名に含まれているため、ファイル名には含めない）。

- `requirements.md` — 要件定義書
- `design.md` — 基本設計書
- `tasklist.md` — 実装タスク一覧

### `dbt/`
dbtプロジェクト一式を格納する。リポジトリ直下に混在させず、専用フォルダに閉じ込めることで、ドキュメント（`docs/`・`.steering/`）とコードを明確に分離する。

- `models/staging/<ソース名>/`：ソースシステムごとに、生データを1:1でクレンジングする層（型変換・リネーム等の最低限の加工）
- `models/intermediate/`：複数のstagingモデルを組み合わせる中間加工層（必要な場合のみ作成）
- `models/marts/`：分析・可視化で実際に利用する最終形のテーブル
- `seeds/`：CSVで持ち込む静的なマスタデータ
- `macros/`：再利用可能なSQLの部品
- `tests/`：`schema.yml`に書ききれない独自のテストロジック

モデルの詳細設計・テスト定義・テスト証跡は、`schema.yml`および`dbt docs`に委譲する（`CLAUDE.md`参照）。

### `ingestion/`
CSVデータをS3等のクラウドストレージへアップロードする等、データ取り込みに関わるスクリプトを格納する。

### `sample_data/`
開発・動作確認用のダミーデータを格納する。実データと同じヘッダー構成・想定される値のパターン（返金時のマイナス金額、未分類データ、複数媒体混在等）を含む架空のデータとし、個人情報は一切含まない。Git管理の対象とする。

## 本番データ（実データ）の扱いについて
マネーフォワードからエクスポートした実際のCSV（個人の金融情報を含む）は、本リポジトリには一切含めない。S3等のクラウドストレージにのみ格納し、Gitの管理対象外とする。開発・動作確認時は`sample_data/`のダミーデータを利用する。

具体的な格納先・接続方法は「接続先一覧」（`docs/backlog.md` 016番）に別途整理する。
