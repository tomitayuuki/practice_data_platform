# 要件定義書（作業単位）

## 目的
`docs/development-standards.md`のGit規約（4.1のブランチ保護、4.3のCIによる自動コードレビュー）を実際に構築する。featureからmainへのPR作成・更新時に自動でコードレビューが実行され、レビューを通過しない限りmainへマージできない状態を実現する。

## スコープ

### 対象
- PRの作成・更新（追加push）をきっかけに自動でコードレビューを実行する仕組み（GitHub Actions）
- レビュー結果を、PR上で確認できるようにする
- `main`ブランチにブランチ保護ルールを設定し、レビューのチェックを通過しない限りマージできないようにする
- レビュー処理に必要な認証情報の安全な管理（GitHub Secretsを利用し、リポジトリに直書きしない）

### 対象外
- レビュー指摘の自動修正（指摘への対応は引き続き人が行う）
- コードレビュー以外のCI項目（lintや`dbt test`の自動実行等）。必要になった時点で別途検討する

## 要件
- PRを作成・更新すると、自動でコードレビューが起動すること
- レビュー結果が、PR上で確認できる状態になっていること
- レビューのチェックが通っていない状態では、`main`へのマージ操作ができないこと
- 認証情報はリポジトリに含めない・Gitで管理しない（`CLAUDE.md`のデータ取扱いの原則に準拠）

## 受け入れ基準
- 試験用のPRを作成し、実際にCIが自動起動してレビュー結果が確認できること
- レビュー未完了、またはレビューが失敗した状態でマージ操作がブロックされることを確認すること
